Crypto vol lab

A volatility surface pipeline for Deribit options, built so that every layer proves itself before the next one is allowed to exist.

Most volatility surfaces look fine. The interesting question is how you would know if yours were wrong.

This project builds an arbitrage-free implied volatility surface from live Deribit options — forward extraction, implied vol inversion, SVI and SSVI calibration, then a mean-variance allocation on top. What makes it worth reading is not the calibration. It is the order, and the gates between the stages.

The result that sets the design

Before writing any calibration code, I wrote a test that asks what happens if the forward is slightly wrong. The answer decided the architecture.

A 99 basis point error in the forward manufactures a 3.58 volatility point shift in the risk reversal.

That is a stable, persistent, tradeable-looking skew. It is entirely an artefact. Nothing downstream can detect it, because every stage after the forward inherits the error and stays internally consistent.

This is why forward extraction is stage 2 and calibration is stage 4. Not convention — consequence. If you fit a beautiful SVI smile on top of a bad forward, you get a beautiful, arbitrage-free, completely fictional skew, and every diagnostic you have will agree with it.

The stages

  1. Capture and normaliseDeribit's BTC and ETH options are inverse — a quote of 0.0210 means 0.0210 BTC. Conversion to USD happens at the index, not the forward, because the premium is paid now.
  2. Forward extractionPut-call parity regression per expiry. The index cancels: in native units the slope is -D/I and the intercept D·F/I, so F = intercept / -slope needs no index at all.
  3. Implied volatility inversionBlack-76 on out-of-the-money quotes, validated against the venue's own mark IV. The venue's number is used only to check, never as an input.
  4. SVI calibrationPer-expiry fit in total variance w = σ²T, with Lee's wing bound as b(1+|ρ|) ≤ 2.
  5. SSVI arbitrage gateDurrleman's condition across the surface. On failure the fit is redone jointly under SSVI and the cost in fit quality is reported.

Every stage has a number it must hit

Each stage publishes acceptance criteria, and quotes that fail are quarantined with a reason code rather than deleted — so rejection counts become a daily time series. A sudden change means either the market moved or the feed broke, and you need to know which.

  • Parity regression r² must clear 0.999
  • Extracted forward must sit within a few basis points of the venue's own
  • Inversion failures must stay under 1%
  • SVI weighted fit error must stay under 0.5 volatility points
  • durrleman_min must be non-negative — negative means negative risk-neutral density

Stage 5 is a hard gate, and the rule when it fires is deliberate: accept the worse fit. An arbitrage-free surface with larger residuals is usable. A tight fit with negative density is not.

Diagnostics point upstream

A rising inversion failure rate at moderate moneyness is the signature of a bad forward from stage 2, not a solver problem. The output is designed so that symptoms name their likely cause rather than sending you to the wrong layer.

Anyone can reproduce it

There is no API key, no account and no subscription anywhere in this project. Live chains come from Deribit's public endpoints. Historical quotes come from the Tardis free tier, which serves the first day of each month — roughly twelve real quote-level days per year, enough to build and validate the calibration now instead of waiting months for a private archive. The full options trade archive is free from Deribit directly.

The trade archive is not used to build surfaces — prints are far too sparse across strikes. It is used for the cost model: every print carries its direction, so you can measure where trades actually happen relative to mark. Assuming a flat haircut instead is how a strategy looks profitable on paper and is not.

Running it

In this order. The first command needs no network — if it fails, the problem is the environment, not the market.

python test_synthetic.py         # the numerics            5/5
python test_loaders.py           # the loaders             4/4
python test_svi.py               # calibration and gates  11/11
python test_portfolio.py         # the allocation layer     7/7
python run_surface.py --offline  # the plumbing, stages 0-5
python run_surface.py BTC        # live capture

The synthetic test generates option prices from known parameters, runs them back through stages 2 and 3, and checks the parameters are recovered. Everything above the last line runs without a network.

The allocation tests include a deliberate negative control: on pure noise, mean-variance must show no out-of-sample edge over equal weight while still paying turnover. A method that looks good on noise is measuring nothing.
